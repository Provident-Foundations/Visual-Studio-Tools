# Code review

Open a solution or project, then choose **Code Review** and either a category or **Review All Categories**. Progress appears in the busy overlay; **Cancel Analysis** keeps the previous results. Completed advisories and review-coverage notes appear in the Error List. Double-click a row with a file and line to open the editor at that location. Manual-review rows identify files requiring human review. **Save Review Report** saves the latest completed review as JSON, including locations.

Every review scans C# (`.cs`) and Visual Basic (`.vb`) files on disk recursively under the selected solution or project directory, its containing Git repository if present, and loaded project directories, plus explicitly listed source items, including linked files. SQL files are included only as database migrations: their filename must contain `migration` or `migrations` as a word separated from other letters, or they must be inside a directory named `migration`, `migrations`, or `migrate` (case-insensitive). Migration SQL files are reviewed only in the Database category. Other SQL files and all other file types are excluded. Migration scripts using other naming conventions require manual review.

Files are included regardless of Git status, including unchanged, untracked, ignored, staged and generated files; Git is not required. Large build or dependency directories can make reviews slower and produce many findings. The review uses the current disk contents, not unsaved editor contents or deleted files. Directory traversal excludes Git metadata (`.git`) and linked directories; explicitly listed source items are still included. Unloaded projects, missing linked files and unresolved source items are reported. The report records the selected scope and has no base commit. Visual Basic files are included for manual review; no Visual Basic automated checks are implemented.

Automated checks currently cover C# constant naming, coalescing to `string.Empty`, empty catches, unbraced `if` statements, TODO/FIXME comments, and migration SQL `IF EXISTS` guards. These are advisories requiring context, not proven defects. The remaining checklist rules—including architecture, testing, dependency injection, control flow, and reuse—require manual review. A category without an automated check is not considered clean. The tool does not run subagents, accept PR/branch/path scopes, dynamically load the checklist, or make fixes.
